# Technical Specification - LX790 WiFi Extension

## 1. System Architecture
The system is built on an ESP32 microcontroller using the Arduino framework with FreeRTOS for multi-tasking. It intercepts the communication between the mower's mainboard and the display unit. It uses a dual-core approach to separate timing-critical hardware sniffing from the network stack.

### 1.1 Task Structure
The application is divided into two main FreeRTOS tasks pinned to different cores:

- **TaskHW (Core 0)**: 
    - Handles low-level hardware communication (TM1668 sniffing, button injection).
    - Manages WiFi connectivity (Station mode & Captive Portal).
    - Processes the command queue (`cmdQueue`).
    - Updates the system state and sends it to `stateQueue`.
- **TaskWeb (Core 1)**:
    - Hosts the asynchronous web server.
    - Serves static files from SPIFFS.
    - Provides a REST API for status monitoring and command execution.
    - Manages UI updates and system logging.

## 3. Hardware Components

### 3.1 Microcontroller (ESP32)
- Dual-core 240MHz Xtensa® LX6.
- Integrated WiFi/Bluetooth.
- Utilizes SPIFFS for web resource storage and EEPROM/Preferences for persistent configuration.

### 3.2 Hardware Abstraction Layer (HAL)
A polymorphic HAL allows supporting different hardware versions (V1.0 and V1.1):
- `HAL_LX790_V1_0`: Original implementation using I2C slave mode to listen to display updates.
- `HAL_LX790_V1_1`: Updated pin mapping and logic for version 1.1 hardware using TM1668 SPI sniffing.

### 3.3 Display Controller Sniffing (TM1668)
The ESP32 "sniffs" the SPI-like protocol used by the TM1668 display controller:
- **Signals**: CLK (Clock), DIO (Data), STB (Chip Select).
- **Protocol**: 3-wire serial interface, LSB first.
- **Method**: The HAL identifies `DISPLAY_CMD_ADDRESS (0xC0)` to capture segment data for the 4 digits and additional symbols (Battery, Clock, Lock).

### 3.4 Button Injection
Remote control is achieved by pulling physical button lines to GND via ESP32 GPIOs:
- **Buttons**: Power/IO, Start (Up), Home (Down), OK, Stop.
- **Method**: GPIOs are configured as `INPUT` (high impedance) when inactive and `OUTPUT LOW` to simulate a press.

## 4. Communication & Data Flow

### 4.1 Inter-Task Communication
- **`stateQueue`**: A FreeRTOS queue (`QueueHandle_t`) used to push `LX790_State` updates from `TaskHW` (Core 0) to `TaskWeb` (Core 1).
- **`cmdQueue`**: A FreeRTOS queue used to send `CMD_Type` commands from the Web/Serial interface to the hardware task.
- **`queueButton(BUTTONS btn, int delay)`**: Helper function that sequences a `BTN_PRESS`, a `WAIT`, and a `BTN_RELEASE` into the `cmdQueue`.

### 4.2 External Interfaces
- **Web UI**: Responsive HTML/JS interface served from SPIFFS.
- **REST API**: 
    - `GET /status`: Returns full state as JSON (generated by `jsonStatus()`).
    - `GET /cmd?parm=[BTN]&value=[0/1]`: Executes button presses or system commands.
- **Serial Console**: 115200 baud, supports manual configuration (`config`), reboot, and WiFi mode switching (`portal`, `client`).

## 5. Software Stack
- **Framework**: Arduino ESP32.
- **JSON Library**: ArduinoJson (v7.x).
- **Web Server**: WebServer (built-in) / ESP32 Web Server logic.
- **Storage**: SPIFFS for files (Web UI, logs), EEPROM for settings (debugLog, autoUnlock).
- **Other**: DNSServer for Captive Portal, mDNS for hostname resolution, ezTime for NTP sync.

## 7. Implementation Details
- **TM1668 Decoding**: Raw segment data is converted into ASCII characters via a lookup table (`decodeChar`) in `LX790_util.cpp`.
- **Mode Detection**: The system analyzes display patterns and system flags to infer the mower's state (Mowing, Charging, Error, etc.).
- **Auto-Unlock**: A state machine in `TaskHW` can automatically sequence the PIN entry if the `lock` flag is detected on the display.
- **Logging**: `TaskWeb` manages rotating logs (`system.log`, `debug.log`) stored in SPIFFS, capturing state changes and debug information.
